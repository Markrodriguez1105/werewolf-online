# Game modes implementation agreement

User confirmed four modes and app-displayed moderator narration (host remains a player). Latest user description overrides earlier infection proposal: only ordinary Villagers are infectable; Seer/Guard are not. Classic deck is used for Classic, Infected Village, and Secret Pact. No Seer replaces the Seer and one ordinary Villager with Witch and Drunk; player count stays fixed. Optional Guard remains available in every mode.

## Rules

- Classic: current behavior unchanged.
- No Seer: Witch and Drunk, no Seer. Drunk belongs to village, role-plays being tipsy in discussion, ordinary vote, no night action. Witch gets one heal and one kill for the entire match, may use both in one night, may save herself if marked by wolves, cannot poison herself. Healing cancels the wolf attack only; Guard protection does not block poison. Healing and poison on the same victim still kills that victim by poison. Guard may already protect raw wolf victim; Witch sees raw target, not Guard's target. A chosen heal is consumed even if Guard also protects. Deduplicate double-target deaths.
- No Seer night has a second fixed-length `witch` phase after wolves' choices lock. Duration uses settings.nightSeconds. All players see that night continues, only Witch gets victim and potion UI. Both night stages always run their full timer in No Seer, including after Witch death/exhaustion; this avoids activity timing leaks. No deaths or victory checks before all night effects resolve. Witch attacked by wolves may still act; Seer normally absent. Missing Witch action uses no potions. Choices can be revised; potions spent only at resolution. New engine export submitWitchAction(game,id,choice).
- Infected Village: once per game the living wolves may unanimously agree on kind=infect plus same target instead of a normal kill. The attempt is spent on unanimous resolution, even if target is protected, ineligible, or killed by another effect. Only an ordinary Villager (role `villager`) surviving all night effects converts at dawn. Guard protection blocks conversion. Target eligibility must NOT be disclosed through UI filtering or immediate rejection: wolves may select any living nonwolf; a special-role target simply fails at resolution. Private notification: 'You are now a Werewolf.' New wolf learns living pack; pack learns new teammate; no public conversion announcement. Next night can act as wolf. Prior team ability lost. No Seer-only Witch/Drunk in this mode. Infection uses an attack rather than granting an extra attack. After infection spent, requests for infect fail. Wolves must agree on both kind and target or no attempt/no kill; missing selections also no attack. Public deck counts are INITIAL composition; don't update settings.wolves on conversion. Guards can protect wolves under existing rules, but no self/consecutive same targets.
- Secret Pact: randomly choose two distinct players independently of role assignment. Each privately knows partner ID/name, not role (unless normal wolf teammate information already reveals it). Keep original teams and win conditions, including eliminated teammates sharing team victory. Whenever either dies by night/day, eliminate their living partner too before one final victory check. Guard blocks a direct wolf attack, not a death caused by the bond. Public role reveals remain normal. Pact identity stays private while both alive. Fixed link for match. Random selection must allow either of all players to be chosen; use supplied random() for deterministic tests.
- Keep current Winner union village/wolves. No new neutral team or draw. With one wolf attack + one poison per night and parity checked after every resolution, zero survivors cannot occur from a valid reachable match; do not add speculative draw support.
- Narration: public app 'Moderator' story text per phase, mode-aware and varied by round/outcome. Never include secret target, infection attempt/result, Witch use, or pact identity in public story. Dead names/roles already public may be used. Host can read aloud, no voice/TTS dependency.

## Shared API

src/shared/protocol.ts contains new GameMode, WitchChoice, WolfAction, phase witch, mode on Settings, private view optional fields, and additional authoritative GameState fields. src/shared/modes.ts exports MODE_DETAILS and roleDeck used by UI and engine, preventing deck-count drift.

Game engine API unchanged except:
- submitNightAction(game, playerId, targetId, kind: WolfAction = 'kill'). Only wolves may use infect; guard/seer plain actions use kill default but do not interpret it as a kill. Nonwolves explicitly supplying infect must be rejected.
- submitWitchAction(game, playerId, choice: WitchChoice): void.

GameState.nightActions remains actor->target. wolfActions holds wolf kind selections; pendingAttack locks raw unanimously chosen target/kind before Witch stage. During Witch stage preserve guard selections until resolution. witchChoice/potions separate. All new GameState/private fields must be cloned in view; never expose internal state in RoomView. GameView.witch only for current living Witch; attackTargetId only during witch phase. For infected player private wasInfected flag; pactPartnerId only to two partners; infectionAvailable/wolfActionSelections only living wolves. No private information in event logs. Personalized views must remain mutation-isolated.
